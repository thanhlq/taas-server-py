# File Manager — developer guide

Backend of the File Manager: `libs/ews/src/ews/files` (module map: its `CLAUDE.md`). Specs: `taas-specs/files/`
(`files-architecture.md` = how it works, `files-api.md` = endpoints, `decisions.md` = ADR-1 … ADR-13).

## Run it locally

| Need | How |
| --- | --- |
| Tables | `uv run --offline python -m db.migrations upgrade head` (revision `8c4f2d6b1a95` adds the pipeline, previews, index; creates `pg_trgm` when allowed) |
| API + pipeline | `start_fastapi_ews_api.sh` — `FILES_PIPELINE=api` (default) runs thumbnails, text index and trash retention in the API process |
| Worker instead | `FILES_PIPELINE=worker` for the API **and** `ews_worker` (`start_worker.sh`); the worker initialises the storage resolver itself |
| Storage | Whatever `STORAGE_*` / `AWS_*` resolve to (R2, S3, RustFS …); `FILES_DELIVERY=proxy` works with any of them |
| One-off backfill | `from ews.files import drain; await drain()` (every pending version; migration leaves existing versions `pending`) |

## Pipeline in one minute

1. An upload commits the version with `pipeline_status = 'pending'` and calls `_pipeline.kick()`.
2. The runner claims a batch (`FOR UPDATE SKIP LOCKED`), reads each object, runs `_derive.derive(bytes, mime)` in a
   thread, writes `derived/files/{node}/{version}/{variant}.webp`, then saves `taas_file_previews`,
   `taas_file_contents` (current version only) and the version's statuses / `meta`.
3. Lists add `preview_status`, `thumbnail_url`, `placeholder` (`_previews.thumbnails`); the web refreshes while
   `pending`.

## Add a file type

1. `_derive.py`: detect it in `sniff` (magic bytes), add a branch in `derive` that fills `out.images` (`thumb`, maybe
   `preview`), `out.placeholder`, `out.text` (through `_set_text`) and `out.meta`. Stay pure: bytes in, `Derived` out;
   guard against hostile input (sizes, decompression, archives).
2. Heavy or slow converters (LibreOffice, FFmpeg): not in `derive` — they belong to the lazy jobs of ADR-11
   (`taas_file_jobs`, sandboxed workers).
3. Tests: `tests/unit/test_files_derive.py` (pure), then an API case in `tests/unit_dev/test_files_pipeline_api.py`.
4. Re-run existing files: `POST /api/v1/files/nodes/{id}/reprocess`, or set `pipeline_status = 'pending'` in bulk.

## Signed URLs

Always `_delivery.signed_url(tenant, drive.settings, node.id, key, mime, filename, inline=…, view=…)` after the
permission check. Never cache a URL in the database; the expiry is rounded so the same URL repeats within a window.
Revoke with `_drives.revoke_links(drive)` (bumps `settings.url_epoch`). Reuse `ews.shared.SignedUrlCache` /
`rounded_expiry` for any other app's URLs.

## Gotchas

- A development API with `FILES_PIPELINE=api` on the **shared database** also claims versions created by tests or
  other processes. It reads its own storage: versions of an in-memory test storage end as `object missing in storage`.
  `test_files_pipeline_api.py` requeues them (`_ready`); set `FILES_PIPELINE=off` on scratch APIs that should not process.
- PDFium (`pypdfium2`) is not thread-safe: `_derive` serializes it with a lock.
- `taas_file_contents.tsv` is generated by PostgreSQL (`to_tsvector('simple', text)`); never write it, and remove NUL
  characters from text (`clean_text`).
- The trigram index exists only where `pg_trgm` could be created; name search still works without it, slower.
